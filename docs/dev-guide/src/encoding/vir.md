# The VIR intermediate representation

VIR ("Viper IR") is Prusti's own intermediate representation, defined in the [`vir`](https://github.com/viperproject/prusti-dev/tree/master/vir) crate. It closely mirrors Viper's own AST (fields, predicates, domains, ADTs, methods with a CFG body, pure functions, expressions, ...) but adds a few conveniences that make it more pleasant to construct programmatically. Every encoder in `prusti-encoder` ultimately produces VIR nodes; the conversion of a finished `vir::Program` into actual Viper AST (JVM objects) is a separate, later step handled by [`prusti-viper`](../pipeline/viper.md#encoding-vir-to-viper).

## Arena allocation

All VIR nodes are allocated in a [`bumpalo`](https://docs.rs/bumpalo) arena owned by a `VirCtxt`, and referred to by shared references with the arena's lifetime (conventionally called `'vir` or `'tcx` throughout the codebase). This means the same node can be shared by multiple parents without cloning, at the cost of everything being immutable once built.

> - [`vir/src/context.rs` - `VirCtxt`](https://github.com/viperproject/prusti-dev/blob/master/vir/src/context.rs) - owns the arena (`VirCtxt::alloc`/`alloc_slice`/`alloc_str`) plus the compiler's `TyCtxt`, the current MIR bodies, and the typed specification map.
> - [`vir/src/context.rs` - `with_vcx`/`init_vcx`](https://github.com/viperproject/prusti-dev/blob/master/vir/src/context.rs) - there is a single, thread-local `VirCtxt` for the whole encoding process (initialized once in `prusti_encoder::test_entrypoint`); `with_vcx(|vcx| ...)` is the standard way encoders get access to it.

Each node kind has two related type definitions, distinguished by a naming convention used throughout `vir`: a `...Data` struct holding the actual fields, and a plain type alias for a shared reference to it (e.g. `ExprData<'vir, T>` and `pub type Expr<'vir, T> = &'vir ExprData<'vir, T>`, in [`vir/src/data.rs`](https://github.com/viperproject/prusti-dev/blob/master/vir/src/data.rs) and [`vir/src/refs.rs`](https://github.com/viperproject/prusti-dev/blob/master/vir/src/refs.rs)). Encoders almost always work with the reference alias.

## Expressions are statically typed by a phantom Viper type

VIR expression types are parameterized over a marker type `T: CompType` representing the expression's Viper type — `Bool`, `Int`, `Perm`, `Ref`, `Set`, `Multiset`, `Seq`, `Map`, and a few Prusti-specific ones (`CSnap`/`PSnap` for the two snapshot-domain flavours used in [type encoding](types.md), `TyVal` for reified type-info values), plus erased variants `Prim`/`Snap`/`Dyn` for cases where the concrete type isn't statically known. `vir::refs` defines convenient aliases for each combination, e.g. `ExprBool<'vir>`, `ExprInt<'vir>`, `ExprDyn<'vir>`. This lets many "used a permission expression where an integer was expected"-style mistakes be caught by the Rust compiler itself while constructing VIR, rather than surfacing later as a cryptic Viper type error.

## Generic ("Gen") nodes and reification

A second family of node types, suffixed `Gen` (e.g. `ExprGenData<'vir, Curr, Next, T>` in [`vir/src/gendata.rs`](https://github.com/viperproject/prusti-dev/blob/master/vir/src/gendata.rs)), is additionally parameterized over a "local context" type `Curr`. This is used to build expression *templates* that are not yet fully concrete — for example, the body of a predicate or the postcondition of a pure function can be constructed once, generically over "whatever the receiver/arguments will be called", and later specialized (**reified**) once those are known, via the [`Reify`](https://github.com/viperproject/prusti-dev/blob/master/vir/src/reify.rs) trait:

```rust
pub trait Reify<'vir, Curr> {
    type Next: Sized;
    fn reify<'tcx>(&self, vcx: &'vir VirCtxt<'tcx>, lctx: Curr) -> Self::Next;
}
```

An `ExprKindGenData::Lazy` node additionally allows deferring the actual construction of a subexpression until reification time, by storing a closure to be called with the eventual context. This pattern shows up constantly in the [pure encoder](pure.md) and in [type encoding](types.md), wherever an expression needs to be built once and instantiated at multiple call sites with different concrete arguments.

Most of the boilerplate needed for the `Data`/`Gen` type family (hashing, the `Reify` impl, serialization) is generated by derive macros from the sibling [`vir-proc-macro`](https://github.com/viperproject/prusti-dev/tree/master/vir-proc-macro) crate (`#[derive(VirHash, VirReify, VirSerde)]`), rather than hand-written per node kind:

```rust
#[derive(VirHash, VirReify, VirSerde)]
pub struct BinOpGenData<'vir, Curr, Next> {
    #[vir(reify_pass)]
    pub kind: BinOpKind,
    pub lhs: ExprGenDyn<'vir, Curr, Next>,
    pub rhs: ExprGenDyn<'vir, Curr, Next>,
}
```

If you need to add a new VIR node kind, this is the pattern to follow: add the `...GenData` struct (with the derives) to `gendata.rs`, a type alias in `genrefs.rs`, and (if it also exists in a "final", non-generic form) a `...Data`/alias pair in `data.rs`/`refs.rs`.

## Convenience macros

[`vir/src/macros.rs`](https://github.com/viperproject/prusti-dev/blob/master/vir/src/macros.rs) defines a family of `vir_*!` macros (`vir_format!`, `vir_local_decl!`, `vir_type!`, `vir_predicate!`, ...) that make constructing common node shapes less verbose than calling `VirCtxt::alloc` directly; they are used pervasively throughout `prusti-encoder`.

## Identifiers, spans, and errors

- [`vir/src/viper_ident.rs` - `ViperIdent`](https://github.com/viperproject/prusti-dev/blob/master/vir/src/viper_ident.rs) - a validated, sanitized Viper identifier (`ViperIdent::sanitize` mangles disallowed characters like `<`, `>`, `:` from Rust-derived names such as monomorphized generic function names).
- [`vir/src/spans.rs` - `VirSpan`/`VirSpanManager`](https://github.com/viperproject/prusti-dev/blob/master/vir/src/spans.rs) - VIR nodes carry an optional `VirSpan` pointing back to the originating Rust source location; these are converted to Viper `Position`s (carrying just an integer id) when [converting to Viper AST](../pipeline/viper.md), and looked back up from that id when [reporting errors](../pipeline/report.md) (`VirCtxt::backtranslate`).
